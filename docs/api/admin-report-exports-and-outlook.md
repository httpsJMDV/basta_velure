# Admin report exports, payment charts and outlook

`GET /api/v1/admin/reports/export?format=pdf|xlsx` requires an active admin and is throttled to 20 requests/minute. It accepts the same `from`/`to` inclusive Manila dates or `range` presets as other admin reports, plus `interval=daily|monthly`. Default format is XLSX. Long windows over 366 days use monthly buckets. Invalid formats/date ranges return 422. Responses are downloadable real PDF/OOXML workbooks, private/no-store with nosniff headers; export errors remain JSON and the web download helper displays their message.

The export reuses AdminAnalyticsService and ReportDocument, without recalculating commissions or altering payments. It includes summary KPIs, selected daily/monthly performance, **all categories**, top 15 sellers, GCash/COD order value, pipeline and the separately labelled estimated outlook when available. Category sales exclude shipping; GMV includes shipping. Cancelled/returned/soft-deleted orders follow existing exclusions. Payment-channel values are counted order values, not proof of captured cash or settled transfers. Spreadsheet strings use the existing inline-text writer, not formulas.

The web category table shows six rows initially. View all/Show fewer is an accessible toggle with a bounded scrolling table and sticky headings. Exports always include every category, regardless of the table's collapsed state. File names contain the actual selected date range. Downloads are disabled while the new range is loading or failed; request-version checks prevent slower old requests from overwriting a newer selection.

Daily/monthly analytics and dashboard feed add `gcash_volume` and `cod_volume`, grouped by **order placement date in Asia/Manila** using the same counted orders as paymentSplit. Their sums reconcile to the payment summary. The dashboard uses 30 stacked daily bars, blue GCash and green COD, with peso tooltips, zero/missing-data states and aligned chart/footer sections beside commission. It does not create payment events or claim funds were collected.

`GET /api/v1/admin/reports/outlook` uses the same admin/date authorization. It returns `available`, `method`, `points`, and an explanatory `reason` when unavailable. The selected period must cover at least 15 days and end today in Manila. The service reads the previous **14 complete days**, excluding today's partial activity, and requires at least four active days. For each of the next seven days (starting tomorrow), estimated GMV and expected orders equal the mean of that weekday in those two weeks. Fractional expected orders are estimates, not booked orders. Available results include `basis_from`, `basis_to`, `today`, 14 history rows and seven future rows with a rounded `estimated_gmv` total.

The method is a transparent two-week weekday baseline, not AI or a calibrated statistical forecast. It assumes recent weekday patterns repeat; unusual events, cancellations after generation and sparse/demo activity can make it unreliable. Estimates remain separate from recorded KPIs, commissions and financial ledgers, and include demo orders in the underlying data. The website uses solid recorded and dashed estimated lines, labels the method, and explains insufficient history instead of inventing an outlook. PDF and Excel label the future section as estimated.

Additional category sales and placed-vs-counted order charts reuse the selected report data. Existing exports and shipping/merchandise payout formulas are unchanged. This is admin web/shared API work; no Android update is required.
